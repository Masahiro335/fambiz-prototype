# ADR-0001: モノレポ構成とTurborepoの採用

| 項目       | 値         |
| ---------- | ---------- |
| ステータス | 承認済み   |
| 決定日     | 2025-12-01 |
| 決定者     | 開発者     |

---

## コンテキスト

FamBizは `apps/web`（Next.js）と `apps/api`（NestJS）の2アプリケーション、および両者が共有するTypeScript型定義（`packages/types`）・ESLint設定・tsconfig等のパッケージで構成される。

開発初期からフロント・バックエンド間でAPIレスポンス型を共有したい、かつCIをひとつのリポジトリで一元管理したいという要件がある。

マルチリポジトリ構成（polyrepo）を採用した場合、以下の課題が生じる。

- フロント・バックエンドで型定義が二重管理となり、API変更時に不整合が起きやすい
- 共通設定（ESLint、tsconfig、GitHub Actions）をリポジトリ間で同期する手間が増える
- `npm link` や プライベートnpmレジストリが必要になり、ローカル開発の摩擦が増す

---

## 決定

**モノレポ構成（pnpm workspaces + Turborepo）を採用する。**

Y-Statement形式:

> TypeScript製フロント・バックエンドを単一リポジトリで管理し、型定義を共有したいというコンテキストにおいて、型安全なフルスタック開発の維持とCI一元管理のために、pnpm workspacesによるモノレポ構成とTurborepoによるタスクオーケストレーションを採用することを決定した。マルチリポジトリ構成という代替案に比べ、セットアップコストがかかるというトレードオフを受け入れる。

---

## 理由

1. **型定義の単一管理**: `packages/types` にAPIレスポンス型・ドメイン型を集約し、フロント・バックエンドが同一の型を参照できる。型のずれによるバグを未然に防ぐ。

2. **キャッシュによるCI高速化**: Turborepoはタスクの依存グラフを解析し、変更のないパッケージのビルド・テストをキャッシュから復元する。`apps/web`のみ変更した場合、`apps/api`のビルドはスキップされる。

3. **並列実行**: `turbo run build` 一発で依存順を考慮しながら全パッケージを並列ビルドできる。

4. **ESLint / tsconfig の統一**: `packages/eslint-config`・`packages/tsconfig` を共有することでコーディングスタイルの一貫性を保つ。

5. **pnpm採用理由**: npmやyarnより高速かつdisk効率が高い。workspacesサポートが堅牢で、Turborepoとの組み合わせが公式に推奨されている。

---

## 代替案の検討

| 案                              | 内容                                 | 却下理由                                            |
| ------------------------------- | ------------------------------------ | --------------------------------------------------- |
| polyrepo                        | フロント・バックエンドを別リポジトリ | 型定義の二重管理・CI分散                            |
| Nx                              | モノレポツール                       | Turborepoより学習コストが高く、個人開発規模には過剰 |
| yarn workspaces (without Turbo) | yarn + workspaces                    | キャッシュ機能が弱くCI速度の最適化が難しい          |

---

## 影響範囲

- 全アプリ・パッケージは `fambiz-prototype/` リポジトリ直下に配置する
- `turbo.json` でビルド・lint・testの依存順序を定義する
- ローカル開発は `pnpm install`（ルート）→ `pnpm dev`（Turborepoが各appを起動）で統一する
- GitHub ActionsのCI/CDはモノレポのルートに配置し、変更パスに応じてジョブをフィルタする
