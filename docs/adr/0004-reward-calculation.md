# ADR-0004: 報酬計算ロジック（端数切り捨て・集計期間）の設計判断

| 項目 | 値 |
|------|-----|
| ステータス | 承認済み |
| 決定日 | 2025-12-01 |
| 決定者 | 開発者 |

---

## コンテキスト

FamBizの報酬（お小遣い）管理機能では以下の計算が発生する。

- 当月に承認されたタスクの単価（円）の合計
- 目標達成ボーナスの加算
- 複数の子への並行集計
- 月次での確定・リセット

お小遣いは現実の金銭を扱うため、計算ロジックの透明性・一貫性が特に重要である。  
「なぜこの金額になったのか」が親子ともに納得できる仕組みが必要。

---

## 決定

以下の計算ルールを採用する。

Y-Statement形式:

> 家庭内でのお金のトラブルを防ぎ、親子ともに計算結果に納得できる透明性が求められるコンテキストにおいて、計算の単純さと小数点以下の扱いに関するトラブル回避のために、集計期間を「毎月1日〜末日」・端数を「切り捨て」・支払い完了を「親による明示的なアクション」とするルールを採用することを決定した。切り上げや四捨五入という代替案に比べ、わずかながら子どもへの支払いが少なくなる可能性があるが、計算の一貫性と親側の管理しやすさを優先する。

---

## 採用ルールの詳細

### ルール1: 集計期間（毎月1日〜末日）

**決定:** デフォルトの集計期間は「毎月1日00:00:00 〜 末日23:59:59（JST）」とする。

**理由:**
- 月単位の管理は家庭の生活リズムに最も合致する（月末にお小遣いをもらう文化）
- 親が「今月は何回お手伝いしたか」を直感的に把握できる
- 月次評価・目標設定の単位と揃えることで、報酬と評価のズレが生じない

**実装方針:**
```typescript
// 集計期間の境界は必ずサーバーサイド（NestJS）で計算
// タイムゾーンは必ず Asia/Tokyo を使用
function getMonthRange(year: number, month: number): { start: Date; end: Date } {
  const start = new Date(`${year}-${String(month).padStart(2, '0')}-01T00:00:00+09:00`);
  const end = endOfMonth(start); // date-fns
  return { start, end };
}
```

### ルール2: 端数切り捨て

**決定:** タスク単価の合計計算で小数点以下が発生した場合は切り捨てとする。

**理由:**
- 単価設定は整数（円）のみ許可するため、通常は端数が発生しない
- 将来的に単価割引（特定条件で0.9倍等）を実装した場合に備えてのルール
- 切り捨ては「実際に払う額の最小化」であり、親側に有利。家庭内でのトラブルを避けるため、過払いより不足を選択する
- 四捨五入と切り上げは「少数の桁数によって結果が変わる」という複雑さを生む

**実装方針:**
```typescript
// 報酬合計は必ず Math.floor() で切り捨て
function calculateTotalReward(tasks: ApprovedTask[]): number {
  const rawTotal = tasks.reduce((sum, task) => sum + task.unitPrice * task.quantity, 0);
  return Math.floor(rawTotal); // 切り捨て
}
```

### ルール3: 支払い完了は親の明示的なアクション

**決定:** 月が変わっても自動で報酬リセットは行わない。親がシステム上で「支払い完了」ボタンを押すことで初めて累積報酬がリセット（既読化）される。

**理由:**
- 現実のお小遣い支払いは「渡した」という行為が伴う。自動リセットでは支払い忘れが発生しうる
- 「支払い完了」アクションがトリガーとなり、子にも「もらった」という実感が生まれる（教育的効果）
- 支払い完了履歴をDBに保存することで、いつ・いくら支払ったかの記録が残る

**実装方針:**
```typescript
// 支払い完了時のトランザクション
// 1. rewards テーブルの status を 'paid' に更新する
// 2. rewards.paid_at に現在の日時（JST）を記録する
// 3. フロントへ支払い完了を通知する（累積報酬リセット済みとして扱う）
```

## ボーナス（目標達成報酬）の扱い

- ボーナスは通常タスク報酬とは別に集計する
- 親が「目標達成の承認」を行った時点でボーナスが確定する
- 月次支払い完了処理時に通常報酬 + ボーナスの合計が支払われる
- 端数処理は通常報酬・ボーナスそれぞれに対して行い、最後に加算する

```
最終支払い額 = Math.floor(タスク報酬合計) + Math.floor(ボーナス合計)
```

## 代替案の検討

| ルール | 代替案 | 却下理由 |
|--------|-------|---------|
| 集計期間 | 任意期間設定（親が開始日を決める） | 設計複雑化・子どもに分かりにくい |
| 端数処理 | 四捨五入 | 計算結果が直感的でない・四捨五入の閾値で揉める可能性 |
| 端数処理 | 切り上げ | 将来の割引機能導入時に過払いリスク |
| 支払い方式 | 月末自動確定 | 渡し忘れ防止不可・教育的効果薄 |
