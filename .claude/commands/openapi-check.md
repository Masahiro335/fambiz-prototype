# /openapi-check

**引数**: `$ARGUMENTS`（任意。ドメイン指定、例: `auth`、`tasks`。省略時は全ドメインチェック）

実装済みの NestJS Controller が `docs/design/openapi.yaml` の仕様と一致しているかをサブエージェントで**並列検証**します。

---

## 実行手順

1. `docs/design/openapi.yaml` を読み込み、ドメインごとのエンドポイント一覧を把握する
2. 引数でドメインが指定された場合はそのドメインのみ、省略時は全ドメインを対象にする
3. **Agent ツールで各ドメインのサブエージェントを並列起動**する

---

### 各ドメインのサブエージェント（AUTH / GROUP / TASK / GOAL / REWARD）

プロンプト例（tasks の場合）:
```
FamBiz の TASK ドメインについて、OpenAPI仕様と実装の整合性を検証してください。

参照ファイル:
- docs/design/openapi.yaml（tag: TASK のエンドポイント）
- apps/api/src/modules/tasks/ 配下の Controller・DTO

チェック項目:
1. パス・HTTPメソッドの一致
   - OpenAPI に定義されている全パスが Controller に実装されているか
   - 余分に実装されているパスがないか

2. リクエストの型一致
   - requestBody のスキーマと DTO のフィールド・型が一致しているか
   - クエリパラメータが正しく定義されているか

3. レスポンスの型一致
   - 200/201 レスポンスのスキーマと実際の返却型が一致しているか
   - packages/types の共有型と整合しているか

4. 認証要件の一致
   - security: [] の付いたエンドポイントのみが認証不要になっているか
   - それ以外は JwtAuthGuard が適用されているか

5. エラーレスポンスの実装
   - 400 / 401 / 403 / 404 が仕様どおり返却されるか
   - GlobalExceptionFilter を通じて統一形式になっているか

結果: 一致 / 不一致箇所をエンドポイントごとに一覧化
```

---
